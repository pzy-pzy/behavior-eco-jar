## 1. 背景与问题诊断

现状四感不足(娱乐性、持久性、新鲜感、积累感),对应四个结构性原因:

| # | 症状 | 结构性原因(代码位置) |
|---|---|---|
| 1 | 一周内"通关" | 阶段门槛 45/180/480 分钟(`src/model.rs` STAGES),繁盛后 `growth()` 永远钳在 1.0,主进度轴死亡 |
| 2 | 缸没有记忆 | 七个外观特征全是当下状态且离线衰减;永久的只有两个计数器;`metrics.jsonl` 存了 14 天历史无人消费 |
| 3 | 所有人同一只 | 随机种子硬编码(`ui/scene.js` seed=20261022),形态参数全为常量 |
| 4 | "一天"没有叙事 | 跨天仅清零计数器,无以天为单位的循环 |

## 2. 产品方向

> **从"看一只生物长大"(8 小时读完的故事),变成"一代代由你的工作方式塑形的生物 + 一座图鉴"。**

本产品独占的收集逻辑(区别于抽卡/数值收集):

1. **物种 = 终身行为聚合**:signature 系统本来就在给工作方式打分,把终身聚合映射为物种;
2. **收藏 = 工作方式博物馆**:图鉴翻开,每一只都是某段时期的你;
3. **稀有度 = 健康工作方式**:稀有/变异条件设计为鼓励张弛有度,收集目标与产品价值观同构。

## 3. 设计红线(全部功能的验收前提)

- 永不死亡、永不惩罚:毕业是庆祝,缺席有叙事无损失,进度不倒退(沿用现有哲学);
- 不任务化、不打扰:不弹通知、不设每日必须完成的清单;
- 纯本地:无账号、无联网、无遥测;隐私边界不扩大——新增数据全部来自现有分钟桶聚合,仍不含应用名/标题/输入内容;
- **剪影测试**:物种差异化验收标准——纯剪影 + 10 秒动效内可辨认物种。参数微调不算差异化。

## 4. 核心循环

```
孢子落缸(新基因)
   → 孢子期:所有物种同形,无法预判
   → 幼体期:动势先于外形泄密(运动方式开始分化)
   → 成体期:显形时刻,物种锁定 + 仪式
   → 繁盛期:完满
   → 玩家主动"收集它":仪式动画 → 产下下一代孢子 → 收入图鉴
   → 新一代开始;图鉴渐满,稀有种/变异/隐藏槽构成长期目标
```

对诊断的覆盖:#1 进度轴随世代天然重启;#2 图鉴即永久记忆;#3 基因+物种双轴差异;#4 一代 1~3 周,以"代"为叙事单位。

## 5. 功能规格

### 5.1 世代制与收集(P0)

- 每代生物从孢子开始,`active_minutes` 等成长量随代重置;全局维护代数计数(第 N 代)。
- **收集入口**:右键菜单新增"收集它",`stage >= 2`(成体)解锁;stage 3(繁盛)时收集记为"完满收集"。
- **收集流程**:前端仪式动画(绕缸一周 → 产孢 → 光芒收进缸底,复用现有 bubble/burst 管线)→ 后端归档当前代 → 重置生态 → 用新基因生成下一代孢子。
- **初代印记**:第 1 代永远带"初代"印记;旧存档迁移后的当前代同样视为初代。
- 收集永远是玩家主动、庆祝性的;无倒计时、无自动收集、无衰老死亡。

### 5.2 物种判定(P0)

**输入(终身聚合,每秒增量更新)**:

- 五维签名的时长加权均值(focus/calm/rhythm/load/variety;variety 仅在 `variety_known` 时计入);
- 关键事件计数:深专注时长累计、过劳日天数、crunch 后节律恢复事件;
- 24 桶小时直方图(各小时活跃秒数,来自分钟桶时间戳);
- 天数、休息次数、总活跃/专注分钟(现有字段)。

**判定**:评分函数(各物种一个加权贴近度,阈值常量集中定义、边做边调),stage 2 时锁定最高分物种并广播"显形"事件;`active_minutes` 不足最低限度时不锁定(继续按未定型渲染)。

**物种表(P0 六常见种)**:

| 物种 | 图纸 | 判定方向(终身聚合,阈值待调) | 光语言 |
|---|---|---|---|
| 深光种 | 浮伞型 | 高均值专注、低碎切 | 光晕随收缩脉动 |
| 潮汐种 | 冠羽型 | 高节律、休息规律 | 羽冠随节律开合 |
| 群游种 | 群游型 | 高探索、应用多样 | 整群转向时集体闪光 |
| 沉玉种 | 辐射型 | 扛过高负荷期且恢复 | 臂尖五点微光 |
| 晨光种 | 流线型 | 主要活跃在上午 | 金色侧线光带 |
| 夜洄种 | 流线型 | 主要活跃在深夜 | 蓝紫节段渐次发光 |

(P1 增加:琉璃种/栉纹型,高平静+高专注;P3:月轮种/环形,传说。见 §8。)

### 5.3 基因组(P0)

- 每代出生时生成并存入 state.json:随机种子、形变谐波权重、纤毛数量、体型系数、色相微偏、液泡排布、共生体数量;
- `scene.js` 的硬编码种子与形态常量全部改为从基因读取——**同物种两只也不完全一样**(类闪光个体差);
- 基因是变异系统的承载层(P3)。

### 5.4 图纸库(P0 首发 4 张,分批补齐 9 张)

图纸 = 体型 + 生态位 + 运动方式 + 点击反应 + 光语言,五要素齐备才算一张图纸:

| 图纸 | 生态位与运动 | 点击反应 | 批次 |
|---|---|---|---|
| 浮伞型(现有改造) | 中层浮游,收缩-滑行脉冲推进 | 缩一下喷走 | P0 |
| 流线型 | 全域巡游,尾摆滑行,偶尔急冲 | 急游到缸边又回头 | P0 |
| 群游型 | 5-7 个体,简化 boids 群集 | 惊散再聚合 | P0 |
| 辐射型(海星) | 底栖,极慢爬行,臂尖试探玻璃 | 单臂卷曲 | P0 |
| 冠羽型 | 固着缸底,滤食羽冠随水流开合 | 羽冠收拢再展开 | P1 |
| 螺旋型 | 沿缸壁极慢爬行 | 缩进壳里 | P1 |
| 蜿蜒型 | 底层蜿蜒,节段跟随 | 盘绕收紧 | P1 |
| 栉纹型 | 中层缓慢自旋,八列栉板虹彩扫光 | 栉板骤亮 | P1 |
| 环形(传说) | 一枚缓缓旋转的光环 | 光环波动扩散 | P3 |

- **运动即身份**:九种运动模式(脉冲/巡游/爬行/固着/群集/蜿蜒/自旋/贴壁/环旋)动起来一瞬即互相区分;
- 生态位差异化红利:不同物种住在缸的不同位置,为 P3"放归访客"的可识别性铺路;
- 群游型与环形是差异化天花板与传说仪式感,单独投入;
- 现有渲染原语(blob 谐波形变、纤毛曲线、辉光精灵、粒子)复用,每张图纸约 100-200 行绘制+运动代码。

### 5.5 显形机制(P0,期待感引擎)

- **孢子期**:所有物种同形(一枚孢子),完全无法预判;
- **幼体期**:按当前领先候选物种给"混合暗示"(奇美拉阶段:鳍芽与腕芽并存、运动方式先分化),随聚合收敛;
- **成体期**:显形时刻——形态锁定 + toast 通报物种名 + burst 仪式(复用现有管线);
- 显形不是抽卡揭晓,是照镜子:你养出夜洄种 = "最近天天干到凌晨"被可视化。

### 5.6 图鉴面板(P0)

- 入口:右键菜单"图鉴";面板打开期间临时放大窗口(复用 set_ui_scale 的窗口尺寸管线),关闭恢复;
- 已收藏条目:活体渲染小图(**渲染器以冻存基因+特征复现,点开它还在游**)+ 名字 + 物种 + 存活周期 + 终身五维条 + 代数印记;
- 未解锁条目:**物种剪影 + 一句暗示文案**(条件的方向性描述,不透露阈值);
- 隐藏 ??? 槽(P3):无剪影,仅传闻式文案;
- 完成度显示:X / 总槽位;P1 起每物种下挂变种画廊。

### 5.7 物种专属阶段名(P1)

- 阶段名随物种变化:鱼是"卵/稚鱼/成鱼/洄游",螺是"卵/幼螺/成螺/归壳",不再共用"孢子/幼体/成体/繁盛"(通用名仅用于未定型期与图鉴分类)。

### 5.8 命名与性格(P2)

- P0:每代按基因组从音节池自动命名(无输入 UI);
- P2:右键可改名;hover 卡显示性格原型(按终身签名分布归类:"晨型专注派"等,文案池)。

### 5.9 日记(P2)

- 每代活着时,关键事件各留一句(caption 生成器现成):第一次两小时深专注、水最浑的那天……
- 收集时日记随代封存,图鉴条目可读——多年后点开老生物,读的是那段时间自己的编年史;
- 日记文案仅由聚合计数生成,不含隐私字段。

### 5.10 其他已接受方向(P2 池,收藏系统之后)

- 表演与回应:事件驱动的小表演(休息回来跳一段、连续专注满一小时开花一次);
- 每日一句话:hover 卡当日总结;
- 缺席叙事化:长时间不开机 → 结壳休眠,回来有"欢迎回来"仪式(不惩罚、有痕迹);
- 喂食微决策、季相配色:谨慎评估后再排。

### 5.11 演示模式升级(P0)

- `--demo` 压缩跑完"出生 → 显形 → 繁盛 → 收集入库 → 下一代"完整循环(现有 demo 采样管道复用),作为功能展示与自测入口。

- metrics.jsonl、存档原子性、单实例、开机自启等现有机制不变。

## 7. 架构改动清单

**后端(Rust)**

- `src/species.rs`(新):物种注册表(判定方向、图纸、阶段名、暗示文案)+ 评分/锁定函数,纯函数可测;
- `src/model.rs`:Eco 增终身聚合字段与增量更新;阶段门槛常量化(见开放问题 #1);
- `src/store.rs`:Persisted 增字段;generations 目录读写;
- `src/main.rs`:新命令 `collect_creature` / `get_codex` / `rename_creature`(P2);snapshot 增 `species`、`candidates_hint`、`generation`、`creature_name` 等字段;收集/显形事件广播。

**前端(JS)**

- `scene.js` 重构:单体绘制 → `render(spec)` 架构,`spec = {archetype, genome, traits, stage, m}`;九张图纸按批次实现为独立模块(绘制函数 + 运动函数 + 点击反应);
- `app.js`:图鉴面板(复用自检面板样式模式)、显形 toast、毕业入口与仪式、右键菜单增项;
- `index.html` / `style.css`:面板与仪式的样式;
- 帧率策略(24/8/10)、点击穿透、拖拽等现有机制不动。

**测试**

- cargo test:物种判定 fixtures(典型聚合 → 期望物种)、毕业归档流程、旧档迁移、generations 读写;
- demo 模式:一代全流程冒烟;
- 手工验收:剪影测试 checklist(每张图纸截剪影图对比)。

## 9. 范围外(已否决/不做)

- 沉积层、每日结晶、时间回放(积累感初版方案,已被收藏系统取代);
- 托盘被拦截问题(机器环境问题,现有替代入口已足够);
- WebGL/硬件加速(透明 WebView2 下不稳,结论已验证);
- 云端、账号、多端同步、社区分享;
- 通知提醒、任务清单、任何形式的打卡压力。

## 10. 待评审开放问题(需拍板,附建议)

1. **一代时长**:现状 480 活跃分钟到繁盛(重度 2-3 天),偏短。建议新世代门槛提到孢子 0 / 幼体 90 / 成体 300 / 繁盛 900(约 1-2 周一代),阈值作为常量可调。是否接受?
2. **收集提示**:仅手动入口,还是繁盛后给一次性温和 toast("它已经完满了,也许该收集它了")?建议(已定):给一次性提示,不重复。
3. **提前收集**:成体(stage 2)即允许收集但记"提前收集"?还是仅繁盛可收集?建议(已定):允许(stage≥2),日记如实记录,不惩罚。
4. **晨光/夜洄共用流线图纸**:以光语言(金侧线 vs 蓝紫节段)区分是否可接受?建议:接受,P0 图纸数控制在 4 张。
5. **图鉴面板形态**:在 224×300 小窗内滚动,还是打开时临时放大窗口(如 340×460)、关闭恢复?建议:临时放大,复用现有 set_size 管线。
6. **旧档迁移粒度**:按 §6.3 合成估算档案即可,还是要更精细(回溯 metrics.jsonl 重建聚合)?建议:合成估算,metrics 只留 14 天,回溯价值有限。
7. **自动命名的语言风格**:音节池走和风(汐音/澪/宵)、还是中文意译(浮光/晚照)?建议:意译池,按物种混入专属字根。
